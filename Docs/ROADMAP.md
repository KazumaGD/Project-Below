# Project Below — дорожная карта

**Версия:** 0.1 · Черновик для согласования  
Источник геймдизайна: `Docs/GDD.md`. Цель — последовательно проверить один законченный игровой день. Сроки не фиксируются до оценки темпа разработки.

## Этап 0. Подготовка

- [ ] Создать Unity-проект (предложение: Unity 6.3 LTS, Universal 3D/URP, PC).
- [ ] Настроить Git, Unity `.gitignore`, сохранение `.meta` и текстовую сериализацию.
- [ ] Добавить `AGENTS.md`, `Docs/GDD.md`, `Docs/ROADMAP.md`.
- [ ] Подключить Codex к локальному репозиторию и проверить доступ.
- [ ] Создать пустую тестовую сцену, проверить Play Mode и отсутствие ошибок.

Готово, когда проект открывается, сцена запускается и начальное состояние сохранено в Git.

## Этап 1. Исследование

- [x] Настроить ввод движения и обзора; реализовать FPS-контроллер с коллизиями.
- [x] Создать взаимодействие с объектом через луч и подсказку.
- [x] Собрать небольшой ручной graybox из примитивов: старт, коридор, развилка, комната, выход.
- [x] Проверить движение, столкновения и взаимодействие.

Готово, когда один этаж можно исследовать без застреваний и взаимодействовать с тестовым объектом. Бег, прыжок, приседание — только если действительно нужны.

## Этап 2. Атмосфера

- [ ] Настроить тёмное окружение, локальный источник света и простые материалы.
- [ ] Добавить шаги и фоновый звук, тестовый пространственный звук.
- [ ] Проверить видимость, читаемость проходов и производительность.

Готово, когда тестовая локация вызывает напряжение без противников и игрок ориентируется в ней.

## Этап 3. Пошаговый бой

- [ ] Создать явные режимы Exploration и Combat.
- [ ] Создать тестового противника и запуск встречи.
- [ ] Реализовать здоровье, очередность ходов, атаку и защиту.
- [ ] Отобразить доступные действия, здоровье и результат хода.
- [ ] Обработать победу и поражение; заблокировать управление исследованием в бою.
- [ ] Проверить повторные встречи, невозможность двойного хода, корректное разблокирование управления.

Готово, когда бой 1 на 1 проходит от начала до любого результата без зависаний и игрок понимает происходящее. Пока используются простые числовые параметры и заглушки визуала.

## Этап 4. Добыча и возвращение

- [x] Определить данные трёх ресурсов и учёт количества.
- [x] Создать объекты подбора и временный инвентарь вылазки.
- [x] Разделить добычу вылазки и постоянный склад убежища.
- [x] Создать сцену Hub и переходы между убежищем и вылазкой.
- [x] При успешном возвращении перенести добычу на склад ровно один раз.
- [x] При поражении обработать потерю добычи и переход в Hub.

Готово, когда ресурсы можно добыть и доставить, а поражение не дублирует ресурсы и не ломает цикл.

## Этап 5. Убежище и день

- [x] Показать в Hub запасы, номер дня и текущую фазу.
- [x] Реализовать фазы Morning, Expedition и Evening, пропуск вылазки и завершение дня с однократным событием.
- [x] Добавить определения и состояние обитателей, сохранять их в игровой сессии между сценами и днями.
- [x] Показать в Hub карточки и подробные характеристики трёх тестовых обитателей.
- [x] Добавить вечернее распределение Food с выбором пайка, прогнозом и проверкой запасов.
- [x] Применять последствия пайков один раз при завершении дня, при поражении распределять пищу автоматически.
- [x] Добавить утреннее назначение поручений, прогноз и отчёт о работе обитателей.
- [x] Выполнять поручения один раз за день перед ручным или автоматическим распределением пищи.
- [x] Добавить ферму, мастерскую и жилую зону с двумя уровнями и строительством за ресурсы склада.
- [x] Завершать строительство один раз за день и применять бонусы производства и отдыха со следующего утра.
- [x] При поражении автоматически завершать день и открывать следующее утро в Hub.
- [x] Добавить стартовое главное меню, подтверждение перезаписи и возврат из Hub.
- [x] Сохранять утро и вечер в один локальный слот с автосохранением, ручной записью и резервной копией.

Готово, когда вылазка, возвращение, расход ресурсов, поручение и улучшение связаны между собой; после перезапуска состояние восстанавливается.

## Этап 6. Нарратив

- [ ] Создать данные трёх тестовых персонажей и одно условное событие.
- [x] Добавить диалог в Hub с портретами, последовательными репликами и двумя ветками, доступными по тестовой кнопке.
- [x] Проверять переходы между репликами и сохранять сюжетные флаги ответов.
- [ ] Не допускать повторного случайного начисления эффектов события.

Готово, когда диалог возникает в нужном контексте, выбор сохраняется и отражается на состоянии мира.

## Этап 7. Проверка MVP

- [ ] Пройти игровой день с победой и добычей.
- [ ] Пройти день с поражением.
- [ ] Проверить нехватку ресурсов, невозможность купить улучшение без оплаты и повторное сохранение.
- [ ] Проверить звук, интерфейс и переходы между режимами.
- [ ] Собрать самостоятельный билд для Windows и провести игровое тестирование.
- [ ] Зафиксировать замечания и определить следующий этап.

После MVP — вертикальный срез (предложение: 2 этажа, несколько врагов, небольшая сюжетная линия), только затем расширение контента.

## Первая задача для Codex

После создания пустого проекта: прочитать три документа, проверить версию Unity и структуру репозитория, предложить минимальную архитектуру; согласовать спорные решения. Затем реализовать **только этап 1**, начиная с контроллера игрока и тестовой сцены. Не создавать остальные игровые системы заранее.
