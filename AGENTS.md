# Инструкции для Codex — Project Below

## Контекст проекта

Одиночный Unity dungeon crawler: свободное исследование от первого лица, пошаговый бой 1 на 1, убежище в интерфейсе, развитие помещений и визуальная новелла. Основные документы: `Docs/GDD.md` (дизайн), `Docs/ROADMAP.md` (приоритеты). Читай их перед изменениями. Они пока черновые: открытые вопросы не превращай в утверждённые решения без согласования.

## Рабочий процесс

- Перед задачей проверь фактическую версию Unity, рендер-пайплайн, пакеты, структуру проекта и существующие инструкции.
- Меняй только относящиеся к текущей задаче файлы; сохраняй чужие правки. Не выполняй массовые рефакторинги, миграции и обновления пакетов без согласования.
- Если задача существенно неоднозначна, уточни решение или предложи небольшой обратимый прототип с явно указанным допущением.
- Делай итерации небольшими: реализация, проверка, краткая инструкция по настройке и тесту в Unity.
- После задачи сообщай изменённые файлы, результат проверки, шаги в Inspector и известные ограничения. Не утверждай, что Play Mode или сборка проверены, если не удалось их запустить.
- Не создавай будущие механики «на всякий случай». Обновляй GDD/roadmap только в рамках согласованных изменений.

## Технические ориентиры

Предлагаемая база — Unity 6.3 LTS, URP, C#, Windows PC. Фактическая конфигурация проекта важнее предположения. Используй установленную систему ввода, не смешивай подходы без необходимости.

- Разделяй игровые режимы Hub, Dialogue, Exploration и Combat. В каждый момент ввод обрабатывает соответствующий режим. Возвращение из диалога — в исходный режим; победа возвращает в Exploration, поражение — в Hub.
- Держи игровую логику отдельно от её UI-представления и звука, насколько полезно для MVP.
- Используй небольшие компоненты с понятной ответственностью. Не вводи глобальный singleton, DI-фреймворк, ECS или универсальный менеджер без конкретной необходимости.
- ScriptableObject подходит для переиспользуемых определений (предметы, враги, персонажи, улучшения); изменяемое состояние партии храни отдельно. Не изменяй исходные asset-данные при обычном игровом процессе.
- Не смешивай временную добычу вылазки с общим складом. Обработка возвращения, окончания дня, результата боя и выбора диалога не должна выполняться дважды.
- Для сохранений используй явные сериализуемые данные, стабильные идентификаторы и версию формата, когда сохранение появится в дорожной карте.

Создавай каталоги по мере появления реальных файлов. Сторонние ассеты оставляй в отдельных исходных каталогах. Не переименовывай и не перемещай существующие ресурсы без необходимости.

## Код C#

- Имена классов и методов — PascalCase; локальные переменные — camelCase; закрытые поля — единообразно `_camelCase`. Файл MonoBehaviour соответствует имени класса.
- Предпочитай private и `[SerializeField]` для инспекторных ссылок; проверяй необходимые зависимости. Комментарии объясняют причины, а не очевидный синтаксис.
- Избегай лишнего поиска объектов и выделений памяти в Update. Не используй UnityEditor API в runtime-коде; редакторские инструменты держи в Editor.
- Не добавляй пакеты без явной необходимости и согласования. Не скрывай ошибки без объяснения причины.

## Сцены, префабы и ресурсы

- Для graybox используй примитивы, простые материалы, понятные имена объектов и повторно используемые префабы.
- При создании сцен предпочтительны проверяемые Unity Editor-инструменты с понятной командой меню, если автоматическое создание необходимо. Не перезаписывай пользовательскую сцену. Генерация должна быть безопасной при повторном запуске либо создавать новый явно названный asset.
- Не генерируй GUID и `.meta` произвольно и не ломай ссылки. При добавлении/перемещении сохраняй Unity-метаданные; избегай ручных изменений YAML сцен при отсутствии надёжной проверки.
- Если доступ к редактору отсутствует, опиши точные шаги настройки и проверки через Inspector.

## Git и проверки

- Сохраняй Assets, Packages и ProjectSettings вместе с `.meta`; не добавляй Library, Temp, Logs, Obj, UserSettings и локальные IDE/сборочные артефакты.
- Не удаляй untracked/изменённые пользовательские файлы. Не выполняй reset, force push или изменения истории. Коммиты и публикация только по запросу.
- Проверяй компиляцию и Unity Console доступными средствами. Добавляй тесты для чистой логики, если они полезны: очередность ходов, расчёт ресурсов, смена дня и переходы. Ручные сценарии проверяй по критериям roadmap.
- Никаких секретов или токенов в репозитории.

## Приоритет первой итерации

Сначала создать возможность перемещаться, осматриваться и взаимодействовать в небольшом тестовом подземелье. Боевая система, убежище и нарратив начинаются только после завершения предыдущих критериев roadmap.
